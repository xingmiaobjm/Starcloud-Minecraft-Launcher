# USER_MANUAL.md — Starcloud 启动器用户手册（WinUI 3 版）

> 适用于 .NET / WinUI 3 版本（`dotnet/`）。旧 Tauri 版手册已随旧架构弃用。

## 1. 系统要求

- Windows 10 1809（build 17763）或更高，仅 x64
- 无需安装 WebView2 或其他运行库——应用为自包含发布（SelfContained）
- 首次启动游戏需要 Java（可由启动器托管下载，见 §10）

## 2. 界面总览

左侧为常驻导航栏（与 Microsoft Store 一致），右侧为内容区：

| 导航项 | 功能 |
| --- | --- |
| 首页 | 启动面板：选账户、选版本、启动游戏 |
| 版本 | 已安装版本管理（隔离设置、Mod、存档、导出） |
| 下载 | 浏览官方版本清单并安装；搜索社区资源（Mod / 整合包 / 数据包 / 资源包 / 光影包）、管理资源库 |
| 存档 | 跨版本存档聚合、复制到其他版本启动 |
| 联机 | 陶瓦联机（Terracotta）建房/进房，也可接入第三方联机 SDK |
| 运行状态 | 当前这一局游戏在做什么：性能占用、启动配置与 JVM、实时日志、运行历史 |
| 账户 | 管理微软正版、第三方（外置）与 Starcloud ID 账户 |
| 插件 | 安装/启用 `.mclplug` 插件、查看权限与免责声明 |
| Nova | AI 助手：对话、工具执行与许可层（每次执行留操作日志） |
| 启动器日志 / 设置（底部） | 查看启动器运行日志；游戏目录、内存、Java、下载与外观 |

界面跟随系统深浅色与系统强调色；可在设置中改为固定浅色/深色，并可设置内置壁纸或本地图片作为自定义背景。

启动器左上角与任务栏/资源管理器里的启动器图标都是 Starcloud 品牌标记（三个空心方格 + 抬起的黄块与星）：
界面里浅色用黑线版、深色自动换成浅线版，形状完全一致；外部图标是深底圆角方块上的浅线版，
16/24px 的小尺寸自动换成品牌手册的单块版。Nova 的图标保持原样。
深色主题的强调色与浅色主题同为品牌黄 `#FFD322`（此前深色用的是绿）。

## 2.1 联机页

无需公网 IP 或端口映射，与好友直连开黑（由 **Terracotta | 陶瓦联机** 提供技术支持）。首页的
「好友联机」卡片与左侧「联机」是同一个入口。

1. **安装联机核心**：首次进入点「安装联机核心」（约 8 MB，国内镜像优先，可随时取消；进度也会
   出现在调度中心）。
2. **房主**：先在游戏里把世界「对局域网开放」，回到「联机」页点「创建房间」，状态变成
   「房间已创建」后复制邀请码发给好友。
3. **加入**：粘贴邀请码点「加入房间」，状态变成「已进入虚拟局域网」后，在游戏内「多人游戏」的
   局域网世界列表里进入房主的世界。
4. **玩家名**：默认跟随当前账户；也可在状态卡里单独填写（多人同机时有用）。
5. **收尾**：「停止联机」会断开该房间所有人并结束本启动器拉起的核心；「回到空闲」只把核心切回
   待机。用户自己开的陶瓦联机不会被启动器关闭。
6. **第三方联机 SDK**：页面底部「打开清单目录」放入第三方 SDK 的 JSON 清单（字段见
   `docs/designs/2026-09-21-multiplayer-sdk-design.md`），重启启动器后即可在「联机方案」中切换。
7. **排查**：卡在「创建房间中」多半是游戏里没开「对局域网开放」；连不上先确认双方用了同一地区的
   节点（同房间玩家建议同地区）。「查看日志」可看到联机核心自己的日志。

## 3. 首次使用（三步）

1. **安装版本**：进入「下载」页，选择一个正式版（如 1.21.x）点击安装，等待进度完成
2. **配置账户**：进入「账户」页添加账户——微软设备码登录，或你自建的第三方认证服务器账密登录；
   回到首页在右侧选择账户
3. **启动游戏**：首页左侧选择版本 → 点击「启动游戏」大按钮

首次启动时右侧会显示新手引导卡片，三步完成后自动隐藏。

## 4. 首页

左侧为启动面板（卡片）：

- **账户模式**：「正版 / 外置」双切换按钮
  - 正版：从已登录的微软账户中选择
  - 外置：从已添加的第三方认证服务器账户中选择（服务器地址由你自己填写）
- **头像与账户名**：圆形头像显示玩家名首字符
- **账户下拉框**：切换账户
- **版本下拉框**：切换已安装版本；下方显示版本元信息
- **启动游戏**（大按钮，双行）：主行为「启动游戏」+ 当前版本号；启动中显示状态
- **选择版本 / 版本管理**：快捷跳转到下载页 / 管理已安装版本
- **进度条**：安装或下载任务进行时显示

右侧为欢迎语、错误/警告提示条（InfoBar）与三个快捷入口卡片
（下载版本 / 模组资源 / 好友联机）。

## 5. 下载页

- 列表来自 Mojang 官方版本清单（本地缓存优先，秒开）
- 按类型筛选：正式版 / 快照 / 旧版等
- 每行显示版本号、类型、发布时间与「已安装」标记
- 点击安装 → 显示下载阶段（游戏文件 / 本地库 / 资源）、进度百分比与速度
- 安装内容：客户端 jar、全部依赖库、windows natives、全量资源文件（SHA1 校验）

## 6. 模组资源页

搜索框可以直接输入中文：启动器会在后台把中文词翻成英文再去搜（Modrinth / CurseForge 的项目名都是英文），
结果区会标注「已按『Sodium』搜索（MC 百科）」说明实际用的词与来源。翻译顺序是
内置词典 → MC 百科（模组条目里括号中的英文名）→ 机器翻译，只有含中文的关键词才会触发，
翻过的词会记在本地下次直接用；没网时自动退回按原词搜索，不会卡住。

安装 Fabric 加载器：

1. 选择 Minecraft 版本（需已安装原版）
2. 加载器版本默认取最新（可手动选择）
3. 点击安装——启动器会拉取 Fabric profile 并与原版版本合并，
   生成 `fabric-loader-<mc>-<loader>` 版本，出现在首页版本下拉中

## 7. 资源库与装载

社区资源采用「先入库、再装载」两步，下载的内容不会直接塞进版本目录：

资源来源可在下载页「模组资源」筛选卡的**来源**下拉切换：**Modrinth** 或 **CurseForge**。
切换后列表、详情、文件与整合包都来自所选来源；CurseForge 下分类筛选会灰显（两边分类体系不同）。
下载窗顶部也有同一组来源按钮，方便已经打开弹窗时直接换源（版本详情页的内容芯片同样受益）。
若想走 CurseForge 官方 API（而不是默认的社区只读代理），在设置页「下载」卡填入自己的
**CurseForge API Key** 即可；留空则用代理。

- **资源库位置**：`%APPDATA%/starcloud-launcher/library/`，按类别分目录
  （`mods` / `resourcepacks` / `shaderpacks` / `datapacks` / `modpacks`），索引写入 `library.json`
- **入库去重**：入库时按文件 SHA1 计算；库中已有相同 SHA1 的文件时直接复用该条目（不重复占空间）；
  文件名相同但内容不同的文件自动加序号（如 `某某 (1).jar`）
- **资源管理**：下载页右上角「资源管理」打开面板，列出库内全部条目（图标、标题、作者、类别、大小），
  可按 全部 / Mod / 资源包 / 光影 / 数据包 / 整合包 筛选
- **重扫**：手动改动过库目录后点「重扫」，按实际文件修复索引
- **装载**：点条目的「装载」→ 勾选目标版本 → 确认写入；数据包会先让你选择装载到哪个版本的哪个存档
- **暂不装载（仅入库）**：弹窗中选择此项只入库、不装入任何版本，之后可在「资源管理」中随时装载
- **删除**：只删除资源库中的副本与索引，不影响已经装载到版本里的文件

装载 Mod 后会自动检查前置依赖：缺失时提示「补全前置依赖」，可「一键补全」自动下载并装载。

## 8. 版本内容管理

从「版本」页选中一个版本 → 打开行菜单（右键或「…」）→「版本详情」，
页面中的「内容」卡片（在「概览」下方）即为版本内容管理。

- **三分区**：Mod 模组（`mods`）/ 资源包与光影包（`resourcepacks`、`shaderpacks`）/
  存档（每个存档下的数据包 `datapacks`）
- **每行内容**：文件名、状态（启用 / 已停用 / 无法解析）与文件大小，以及「停用 / 启用」「删除」按钮；
  每个分区底部显示该目录的完整路径与「打开目录」按钮
- **停用 / 启用**：停用只是给文件加 `.disabled` 后缀（如 `xxx.jar` → `xxx.jar.disabled`），
  不删除文件，可随时还原
- **无法解析**：该 jar 不是可识别的 Mod（文件损坏或不是 Mod）
- **检查更新**：对已启用的内容逐个按 SHA1 到 Modrinth 反查，列出哪些有可更新版本；
  已停用的内容不参与检查
- **冲突扫描**：扫描游戏目录 `mods` 下的 jar，报告 加载器混装 / 多加载器混合包 / 重复安装 / 文件损坏，
  并给出处理建议
- **拖拽安装**：把文件直接拖到「内容」卡片上即可安装——`.jar` 装为 Mod，`.zip` 装为资源包；
  整合包请到下载页搜索安装

## 9. 整合包导出与导入

### 导出整合包

「版本」页选中一个版本 → 行菜单（右键或「…」）→「导出整合包」。

1. 对话框顶部显示源版本、MC 版本与识别到的加载器（Fabric / Quilt / Forge / NeoForge）
2. **勾选要打包的内容目录**，可多选：
   - 列表默认列出标准内容目录（`mods`、`config`、`resourcepacks`、`shaderpacks`、`datapacks`）
     与该版本目录下实际存在的其他子目录（标注「自定义」）
   - 三个快捷按钮：「仅 Mod 与配置」「全部内容」（不含存档）「全部（含存档）」
   - 底部可手动添加目录名（如 `kubejs`、`schematics`），用于**投影（Litematica）等模组的自定义文件**
     导出；目录必须真实存在
   - 对话框实时显示「预计导出体积（文件数）」
3. 点「导出…」→ 选择保存位置，文件名为 `<版本名>-<日期>.mrpack`
4. 导出完成后显示：可下载文件数（Modrinth 上能按 SHA1 匹配到的）、打包进包内的文件数与总体积

说明：

- 导出格式为 **Modrinth 整合包（`.mrpack`）**，`modrinth.index.json` 中直接给出可在
  Modrinth 下载的文件（含下载地址与 SHA1），其余文件放入 `overrides/`
- 匹配不到 Modrinth 资源时不会失败，会**全部打入包内**（体积可能较大）
- 若未识别到加载器依赖，会提示「导入方需自行选择加载器」——此时导入方仍需手动安装加载器
- 不含存档的导出适合分享；含存档会把你自己的世界一并打包

### 导入本地整合包

入口有两个：

- 「版本」页工具栏「导入整合包」按钮（选择 `.mrpack` 或 `.zip`）
- 直接把 `.mrpack` / `.zip` **拖拽到「版本」页**

1. 启动器先解析包信息，显示包名、MC 版本、加载器与文件数、体积
2. 填写**新版本名称**（默认取包名），并选择是否**版本隔离**：
   - 勾选（默认，推荐）：内容独立存放在 `versions/<新名称>/`，并新建一个版本条目
   - 不勾选：内容直接写入共享的 `.minecraft` 目录，不新建版本条目
3. 点「导入」开始下载与安装；弹窗可「后台导入」，安装完成后提示结果
4. 若包内声明的原版或加载器尚未安装，会**联动自动安装**（原版 → Fabric/Quilt/Forge/NeoForge）
5. 新版本名与已有版本重名时会自动改为「原名 (2)」「原名 (3)」

说明：仅支持 Modrinth 格式（`.mrpack` 或内含 `modrinth.index.json` 的 zip）；
CurseForge 整合包与普通压缩包会给出不支持提示。

## 10. 版本备份与回档

「版本」页选中一个版本 → 行菜单 →「备份与回档」。

### 备份

1. 选择**备份粒度**（三档，可再用下方复选框微调）：
   - **最小**：只备份版本定义（`versions/<版本>/<版本>.json`、同名 `.jar`）与启动器设置
   - **标准**（默认）：该版本的内容——隔离版本备份整个版本目录；共享实例备份
     `mods`、`config`、`resourcepacks`、`shaderpacks`
   - **完整**：标准内容 + 共享 `.minecraft` 目录下的内容目录（用于隔离版本一并留存共享内容）
2. 勾选**附加内容**：世界存档、配置、资源包、光影（随粒度自动预勾选，可手动改）
3. 填写**备份名称**（默认 `<版本名>-<日期>_<时间>`），对话框实时显示预计体积
4. 点「开始备份」，弹窗可「后台备份」；完成后提示备份名称、体积与文件数

### 已有备份 / 回档

对话框下方列出该版本的备份（按时间倒序），每行有：

- **回档**：把该备份的内容覆盖回当前版本；**回档前会自动先备份当前状态**
  （生成名为「回档前自动备份-<时间>」的备份），需二次确认
- **删除**：删除该备份文件与索引记录，需二次确认

底部工具按钮：「打开备份目录」（`<.minecraft>/starcloud/backups`）、「重建索引」
（索引损坏或手工放入 zip 后，按 zip 重建备份列表）。

注意事项：

- **版本正在运行时不可备份或回档**，请先退出游戏
- 备份为 zip 归档；备份与回档均不会删除备份历史（回档只覆盖备份所包含的范围）
- 索引文件为 `<.minecraft>/starcloud/backups/index.json`，可直接复制整个 `backups` 目录迁移

## 11. 启动可靠性

启动器内置一整套「启动 → 运行 → 退出」的可靠性能力，默认开启。

### 实时游戏日志

- 启动页右下角可勾选「显示日志」，实时滚动显示游戏进程的标准输出/错误输出（保留最近 200 行）
- 点「打开日志文件」直接打开本局游戏的日志文件；游戏日志同时写入 `<.minecraft>/logs/`（隔离版本为版本目录下的 `logs/`）
- 可在设置页开启「启动页默认展开实时日志」

### 启动前环境体检

点「启动」后、拉起游戏前，自动检查磁盘空间、路径合法性、写权限、内存档位、Java 可用性、模组数量等：

- **提示级（如模组较多、内存偏高）**：不打断启动，仅在启动页提示
- **阻断级（如磁盘不足、目录只读、Java 缺失、内存档位非法）**：弹出体检对话框，可点「一键修复」自动处理（如套用智能内存推荐值、跳转 Java 下载），修复后再继续启动

### 崩溃诊断与一键修复

游戏异常退出（非 0 退出码）时自动分析原因，弹窗给出：

- **结论与依据**：如内存不足（`OutOfMemoryError`）、Java 版本不匹配、模组冲突等，附带日志证据
- **一键修复**：按诊断结果提供「套用推荐内存」「重装版本」「打开崩溃报告」「打开 mods 目录」「去下载 Java」等按钮
- **让 Nova 看看**：把本次崩溃上下文交给 Nova 助手继续分析

### 自动重试

游戏启动后 8 秒内异常退出时（未手动取消、未重试过、设置开启），自动重试一次（从文件预检起，不重复环境体检）。

### 智能内存

按物理内存 + 模组数量 + 是否装光影，保守估算推荐最大内存：

- 设置页「智能内存推荐」显示推荐依据（如「16 GB 内存 + 187 个模组 → 建议 6144 MB」），可一键「应用为默认最大内存」
- 体检与崩溃诊断也会在内存相关问题上直接套用推荐值

### 防双开

同一版本正在运行时，再次启动会被拦截并提示正在运行的具体版本，需先退出游戏。启动器被关闭后再次打开也能正确识别正在运行的会话。

## 12. 运行状态页

「运行状态」是**当前这一局游戏的全貌**，位于左侧导航「联机」之后。有游戏在跑时页面实时刷新；
没有游戏时显示空状态，可一键回首页启动，或直接看下面的最近运行历史。

### 页面能看到什么

| 分区 | 内容 |
| --- | --- |
| 顶部信息条 | 「运行中」标记、进程 PID、已运行时长（每秒走动）、版本、实例模式（隔离实例 / 共享 `.minecraft`）、最大内存、启动时间 |
| 性能三卡 | 处理器占用（固定 0–100% 量程）、内存占用（自适应量程，副标题给出峰值与线程数）、显卡占用；每张卡带 60 点迷你曲线，标注「采样已暂停」 |
| 启动配置与 JVM | 本局的 Java 路径、`-Xmx / -Xms`、窗口模式与分辨率、实例模式、额外 JVM 参数 |
| 内容与实时日志 | Mod / 着色器 / 资源包数量；游戏日志尾部约 200 行（等宽、可选中），默认自动吸底，向上滚动查看历史时出现「回到底部」，此时不再自动吸底 |
| 最近运行 | 历史会话表格：版本、开始时间、时长、峰值内存、退出状态（异常退出 / 正常退出 / 退出码 N）；默认显示最近 5 局，可「展开全部」（最多 50 局） |

### 五个操作

| 操作 | 说明 |
| --- | --- |
| 打开日志 | 跳到日志页并直接落在**游戏日志**来源（省一步切换） |
| 诊断 | 扫描版本目录找问题，结果就地显示；发现问题时列出前 20 条（版本 · 类型 · 详情） |
| 复制命令 | 复制本局完整启动命令行到剪贴板，按钮短暂变为「已复制」 |
| 结束进程 | 确认后强制结束整个进程树（未保存的进度会丢失） |
| 重启 | 确认后结束当前进程，并回到首页用同一版本重新启动 |

### 采样设置

页面右上「采样设置」可调：

- 采样间隔：**每 1 秒**（默认）/ 每 2 秒 / 每 5 秒
- 「采集 GPU 占用」开关

采样暂停或异常时，三卡会标出「采样已暂停」，页头出现「重试」按钮，点它（或页头刷新图标）即可重新开始采样。

### 跨重启识别与「约」

关闭启动器**不会**影响正在运行的游戏。再次打开启动器时，只要是**上一轮启动器**启动的会话，
本页依然显示「运行中」，此时会标注「上一轮启动器启动」，且时长前带一个「约」字
（时长按锁文件的启动时间推算，可能略有误差）。这种情况下拿不到完整的命令行，「复制命令」不可用。

显卡占用依赖 Windows 性能计数器：系统未开启或计数器不可用时显示「计数器不可用」，
在采样设置里关掉采集则显示「未采集 GPU」——两者都不影响其他数据。

## 13. 账户页

账户页是**列表**（一级）：上面一张 Starcloud ID 卡（登录 / 注册 / 会话管理都在卡里，不再弹窗），
下面是保存的游戏账户卡片流。所有细节都在**二级页**里，交互与下载页一致。

| 入口 | 去的二级页 |
| --- | --- |
| 右上「添加账户」/ 空状态的「添加账户」 | 添加游戏账户（左选身份 + 右填表单） |
| 点账户卡片任意位置 / 卡上的「账户详情」 | 账户详情（形象与皮肤 / 账户信息） |

### 添加账户

二级页左侧选身份：**微软账户** / **第三方账户** / **离线账户**，
右侧就地填写并完成登录，成功后自动回到账户列表并提示结果（全程没有弹窗）。

### 微软正版账户（内置登录窗口）

1. 在「添加游戏账户 → 微软账户」点「使用内置登录窗口登录」→ 启动器打开**内置登录窗口**，窗口顶部显示本次的一次性验证码
2. 验证页就在窗口里打开，验证码已自动填入，直接登录微软账户即可（不想在窗口里登录时，
   点「改用浏览器打开」会复制验证码并跳系统浏览器）
3. 登录完成后窗口自动关闭，启动器完成换票（Xbox → Minecraft）并添加账户、设为默认

登录使用 Minecraft 官方启动器的应用身份。两种方式由
**设置 → 通用 → 使用内置登录窗口**决定（默认开启内置窗口）：开启时走内置窗口，
关闭时走「显示验证码 + 打开浏览器」。内置窗口打不开（例如系统缺少 WebView2 运行时）会
直接报登录失败并给出提示，启动器不会自动改成外置登录——要换方式请到设置里关闭该开关。

### 第三方账户（外置登录）

1. 在「添加游戏账户 → 第三方账户」填写**你自己的认证服务器地址**（Yggdrasil API 根）、用户名与密码
3. 启动器解析服务器地址（支持 `serverLocation` 别名跳转）并完成登录；账户按 UUID 去重保存

> **合规说明**：鉴权令牌只存内存、绝不落盘，密码只作请求参数（不落盘、不写日志）。
> 因此每次重启应用后，首次启动游戏时会**就地弹出对应的登录框**（微软设备码 / 第三方密码）要求重新登录。

### 离线账户

在「添加游戏账户 → 离线账户」填玩家名即可（3-16 位字母、数字或下划线）。
页面会实时算出离线 UUID（`OfflinePlayer:<名字>` 的标准算法），本地存档与局域网身份保持一致。
离线身份不需要、也不会进行任何在线验证。

### 账户详情（二级页）

- **形象与皮肤**：左侧 3D 形象（可拖拽转视角，跟随设置里的走路动画），右侧皮肤库
- **账户信息**：类型、用户名、UUID、认证服务器（第三方）、会话状态（本次运行是否已登录），
  以及「设为默认」「删除账户」；默认账户会显示徽章，用于首页一键启动

账户卡上仍然保留一个「设为默认」快捷按钮；删除账户需要二次确认（只移除本机身份信息）。

### 多皮肤管理（离线 / 第三方 / 正版通用）

在**账户详情 → 形象与皮肤**里管理，版式是主流启动器的「皮肤选择器」：
左边是 3D 形象（拖动旋转、滚轮缩放），右边是两组卡片。

1. **已保存皮肤**：第一格是「添加皮肤」占位卡 —— 点它选本地 PNG，或者把 PNG
   **直接拖进这块区域**（支持一次拖多张）。卡片显示渲染好的小立绘，点卡片即选中并预览。
2. **默认皮肤**：游戏的 9 个官方默认角色（Steve、Alex、Ari、Efe、Kai、Makena、Noor、Sunny、Zuri，
   版型也按官方各取一套），**点一下就会加入皮肤库并应用到当前账户**。
3. **用起来**：选中后点左侧 `应用到该账户`；型号可选「自动（按纹理判断）」/
   「经典（粗手臂）」/「纤细（细手臂）」。
4. **维护**：选中卡片后可 `重命名`、`删除`（删除会自动取消所有账户对它的引用）；
   `取消使用` 让该账户恢复默认形象。链接导入在「从链接导入」一行（走启动器下载引擎）。

不同账户类型生效范围不一样，页面上会按当前账户如实提示：

| 账户 | 「应用到该账户」之后 | `同步到账号` |
| --- | --- | --- |
| 离线账户 | 本机生效：单人游戏与局域网里你能看到（其他玩家通常看到默认皮肤） | 不可用（没有可上传的账号） |
| 第三方账户 | 只在启动器内预览 | 上传到该认证服务器（服务器需实现标准换肤接口） |
| 微软正版账户 | 只在启动器内预览 | 上传到微软账号，所有玩家可见 |

> **版本提示**：启动器通过 `--userProperties` 给离线账户注入皮肤 URL。
> Minecraft **1.19.2 及更早**版本会直接采用（游戏里可见）；**1.19.3 起**客户端要求签名属性，
> 未签名的注入不生效——这些版本里离线皮肤只体现在启动器自己的形象预览上。

## 14. 设置页

分组卡片布局，修改后点击底部「保存设置」（成功弹出「已保存」提示）：

| 分组 | 项 |
| --- | --- |
| 游戏目录 | `.minecraft` 目录路径（版本/库/资源安装位置） |
| 内存分配 | 单滑块设置最大内存（1 GB ~ 自动上限；自动上限按物理内存的 1/4 计算，最低 2 GB、最高 3/4，如 16 GB 内存约 4 GB）；最小内存固定 512 MB |
| 启动可靠性 | 「启动失败自动重试一次」「启动页默认展开实时日志」开关；「智能内存推荐」按物理内存 + 模组 + 光影给出建议值，可一键应用为默认最大内存 |
| Java | java.exe 路径（留空用系统 java）；「检测系统 Java」；「下载 Java 21 / Java 8（Temurin）」一键托管下载 |
| 下载与资源 | 下载并发数（1-64）；资源缓存开关与清空 |
| 通用 | 界面语言（简体中文 / English）、外观（跟随系统 / 浅色 / 深色）、界面动效（跟随系统 / 始终开启 / 关闭）与版本隔离默认值 |
| 背景与外观 | 自定义背景（关闭 / 内置壁纸 / 本地图片）+ 模糊强度 / 不透明度 / 毛玻璃强度；Nova 游戏内浮窗开关 |

Java 托管下载位置：`%APPDATA%/starcloud-launcher/java/<主版本>/`。

### 背景与外观

在「设置 → 通用」分组中可自定义窗口背景，改动立刻预览，无需点击「保存设置」（此项即改即存）：

| 控件 | 说明 |
| --- | --- |
| 背景 | 关闭（纯毛玻璃）/ 内置壁纸 / 本地图片 |
| 内置壁纸 | 6 张随包发布的内置壁纸（极光 / 星云 / 子夜 / 破晓 / 晨雾 / 暖沙），点击缩略图即生效 |
| 图片文件 | 选择本地图片（`.jpg/.jpeg/.png/.bmp/.webp`）；「清除」移除 |
| 模糊强度 | 0–64 px，对背景图做高斯模糊，越大越柔和（0 = 清晰图） |
| 不透明度 | 0.2–1.0，背景图相对窗口内容的通透程度 |
| 毛玻璃强度 | 0–1，亚克力之上的遮罩浓度；勾选「跟随主题」时深色 0.45 / 浅色 0.25 |

背景全局统一（所有页面一致）。若本地图片被删除或移动，启动时会静默回落到「关闭」。

### 界面语言

「设置 → 通用 → 界面语言」可切换全应用文案（默认「简体中文」）：

| 取值 | 说明 |
| --- | --- |
| 简体中文 | 内置源语言（源语言即键），无需附加词典，始终可用 |
| English | 加载随包发布的英文词典（`Strings/en-US.json`），覆盖全部界面文案 |

切换后立即生效（无需重启），并写入设置持久化。词典缺失或损坏时会静默回退到简体中文，不影响启动与功能。品牌名与专有名词（Starcloud、Java、Nova、Mod 等）在任何语言下都保持原样。

### 界面动效与无障碍

「设置 → 通用 → 主题外观」中的「界面动效」控制全应用的动效，默认「跟随系统」（读取 Windows「辅助功能 → 视觉效果 → 动画效果」开关）：

| 取值 | 表现 |
| --- | --- |
| 跟随系统 | 系统开启动画时启用动效；关闭时全应用无动效 |
| 始终开启 | 无视系统设置，始终启用动效 |
| 关闭 | 全应用无动效（切页瞬时完成、卡片无悬浮/按压反馈） |

此项即改即存。开启时：顶层切页与启动进入首页为淡入转场，进入版本详情为下钻转场；版本 / 存档 / 账户等列表卡片悬浮时渐显跟手阴影并轻微上移（不再放大），设置页与 Nova 页的卡片悬浮时轻微放大、按下时轻微缩小。关闭后所有自定义动效消失，不影响任何功能。改动在下次导航或下次进入页面时生效。

无障碍：仅图标按钮（返回 / 刷新 / 更多操作 / 删除等）均带无障碍名称（`AutomationProperties.Name`）与同源工具提示，读屏软件可正确朗读；工具栏与表单控件的输入框均提供标签或占位提示。整体不依赖颜色区分状态（同时有文字或图标）。

## 15. 启动器日志页

- 通过顶部单选切换**启动器日志**与**游戏日志**两种来源（等宽字体只读显示尾部），排查安装/启动问题用
- 游戏日志可在下拉框选择具体某一局会话（按启动时间列出）
- 日志文件位置：启动器日志 `%APPDATA%/starcloud-launcher/logs/`；游戏日志 `<.minecraft>/logs/`
- 从运行状态页点「打开日志」会直接落到**游戏日志**来源（省一步切换）

## 16. 常见问题

| 现象 | 处理 |
| --- | --- |
| 启动游戏报「找不到 Java」 | 设置页 → 下载 Java 21（Temurin），或手动填入 java.exe 路径 |
| 下载速度慢 | 设置页提高「下载并发数」（默认 16） |
| 下载失败 | 网络问题自动重试；失败后 InfoBar 显示原因，可重试安装（已下载文件自动跳过） |
| 微软登录卡住 | 确认内置窗口里已点完「继续」完成授权；提示「内置登录窗口无法启动」时到「设置 → 通用」关闭该开关改用浏览器；令牌过期则重新登录 |
| Fabric 安装失败 | 先确认对应原版已安装（下载页） |
| 游戏启动即崩溃 | 查看游戏目录 `logs/latest.log` 与启动器日志页 |
| 界面颜色不对 | 设置页「外观」切回「跟随系统」 |
