# USER_MANUAL.md — Starcloud 启动器用户手册（WinUI 3 版）

> 适用于 .NET / WinUI 3 版本（`dotnet/`）。旧 Tauri 版手册已随旧架构弃用。

## 1. 系统要求

- Windows 10 1809（build 17763）或更高，仅 x64
- 无需安装 WebView2 或其他运行库——应用为自包含发布（SelfContained）
- 首次启动游戏需要 Java（可由启动器托管下载，见 §10）

## 2. 界面总览

左侧为常驻导航栏（与 Microsoft Store 一致），右侧为内容区：

| 导航项 | 功能 |
| --- | --- |
| 首页 | 启动面板：选账户、选版本、启动游戏 |
| 下载 | 浏览官方版本清单并安装；搜索社区资源（Mod / 整合包 / 数据包 / 资源包 / 光影包）、管理资源库 |
| 模组资源 | 安装 Fabric 加载器 |
| 账户 | 管理离线账户与微软正版账户 |
| 设置 | 游戏目录、内存、Java、下载与外观 |
| 启动器日志（底部） | 查看启动器运行日志 |

界面跟随系统深浅色与系统强调色；可在设置中改为固定浅色/深色。

## 3. 首次使用（三步）

1. **安装版本**：进入「下载」页，选择一个正式版（如 1.21.x）点击安装，等待进度完成
2. **配置账户**：进入「账户」页添加离线账户（或微软登录）；回到首页在左侧选择账户
3. **启动游戏**：首页左侧选择版本 → 点击「启动游戏」大按钮

首次启动时右侧会显示新手引导卡片，三步完成后自动隐藏。

## 4. 首页

左侧为启动面板（卡片）：

- **账户模式**：「正版 / 离线」双切换按钮
  - 正版：从已登录的微软账户中选择
  - 离线：直接输入玩家名（同时可在下拉中切换历史离线账户）
- **头像与账户名**：圆形头像显示玩家名首字符
- **账户下拉框**：切换账户
- **版本下拉框**：切换已安装版本；下方显示版本元信息
- **启动游戏**（大按钮，双行）：主行为「启动游戏」+ 当前版本号；启动中显示状态
- **选择版本 / 版本管理**：快捷跳转到下载页 / 管理已安装版本
- **进度条**：安装或下载任务进行时显示

右侧为欢迎语、错误/警告提示条（InfoBar）与三个快捷入口卡片
（下载版本 / 模组资源 / 好友联机——联机功能规划中）。

## 5. 下载页

- 列表来自 Mojang 官方版本清单（本地缓存优先，秒开）
- 按类型筛选：正式版 / 快照 / 旧版等
- 每行显示版本号、类型、发布时间与「已安装」标记
- 点击安装 → 显示下载阶段（游戏文件 / 本地库 / 资源）、进度百分比与速度
- 安装内容：客户端 jar、全部依赖库、windows natives、全量资源文件（SHA1 校验）

## 6. 模组资源页

安装 Fabric 加载器：

1. 选择 Minecraft 版本（需已安装原版）
2. 加载器版本默认取最新（可手动选择）
3. 点击安装——启动器会拉取 Fabric profile 并与原版版本合并，
   生成 `fabric-loader-<mc>-<loader>` 版本，出现在首页版本下拉中

## 7. 资源库与装载

社区资源采用「先入库、再装载」两步，下载的内容不会直接塞进版本目录：

- **资源库位置**：`%APPDATA%/starcloud-launcher/library/`，按类别分目录
  （`mods` / `resourcepacks` / `shaderpacks` / `datapacks` / `modpacks`），索引写入 `library.json`
- **入库去重**：入库时按文件 SHA1 计算；库中已有相同 SHA1 的文件时直接复用该条目（不重复占空间）；
  文件名相同但内容不同的文件自动加序号（如 `某某 (1).jar`）
- **资源管理**：下载页右上角「资源管理」打开面板，列出库内全部条目（图标、标题、作者、类别、大小），
  可按 全部 / Mod / 资源包 / 光影 / 数据包 / 整合包 筛选
- **重扫**：手动改动过库目录后点「重扫」，按实际文件修复索引
- **装载**：点条目的「装载」→ 勾选目标版本 → 确认写入；数据包会先让你选择装载到哪个版本的哪个存档
- **暂不装载（仅入库）**：弹窗中选择此项只入库、不装入任何版本，之后可在「资源管理」中随时装载
- **删除**：只删除资源库中的副本与索引，不影响已经装载到版本里的文件

装载 Mod 后会自动检查前置依赖：缺失时提示「补全前置依赖」，可「一键补全」自动下载并装载。

## 8. 版本内容管理

从「版本」页选中一个版本 → 打开行菜单（右键或「…」）→「版本详情」，
页面中的「内容」卡片（在「概览」下方）即为版本内容管理。

- **三分区**：Mod 模组（`mods`）/ 资源包与光影包（`resourcepacks`、`shaderpacks`）/
  存档（每个存档下的数据包 `datapacks`）
- **每行内容**：文件名、状态（启用 / 已停用 / 无法解析）与文件大小，以及「停用 / 启用」「删除」按钮；
  每个分区底部显示该目录的完整路径与「打开目录」按钮
- **停用 / 启用**：停用只是给文件加 `.disabled` 后缀（如 `xxx.jar` → `xxx.jar.disabled`），
  不删除文件，可随时还原
- **无法解析**：该 jar 不是可识别的 Mod（文件损坏或不是 Mod）
- **检查更新**：对已启用的内容逐个按 SHA1 到 Modrinth 反查，列出哪些有可更新版本；
  已停用的内容不参与检查
- **冲突扫描**：扫描游戏目录 `mods` 下的 jar，报告 加载器混装 / 多加载器混合包 / 重复安装 / 文件损坏，
  并给出处理建议
- **拖拽安装**：把文件直接拖到「内容」卡片上即可安装——`.jar` 装为 Mod，`.zip` 装为资源包；
  整合包请到下载页搜索安装

## 9. 整合包导出与导入

### 导出整合包

「版本」页选中一个版本 → 行菜单（右键或「…」）→「导出整合包」。

1. 对话框顶部显示源版本、MC 版本与识别到的加载器（Fabric / Quilt / Forge / NeoForge）
2. **勾选要打包的内容目录**，可多选：
   - 列表默认列出标准内容目录（`mods`、`config`、`resourcepacks`、`shaderpacks`、`datapacks`）
     与该版本目录下实际存在的其他子目录（标注「自定义」）
   - 三个快捷按钮：「仅 Mod 与配置」「全部内容」（不含存档）「全部（含存档）」
   - 底部可手动添加目录名（如 `kubejs`、`schematics`），用于**投影（Litematica）等模组的自定义文件**
     导出；目录必须真实存在
   - 对话框实时显示「预计导出体积（文件数）」
3. 点「导出…」→ 选择保存位置，文件名为 `<版本名>-<日期>.mrpack`
4. 导出完成后显示：可下载文件数（Modrinth 上能按 SHA1 匹配到的）、打包进包内的文件数与总体积

说明：

- 导出格式为 **Modrinth 整合包（`.mrpack`）**，`modrinth.index.json` 中直接给出可在
  Modrinth 下载的文件（含下载地址与 SHA1），其余文件放入 `overrides/`
- 匹配不到 Modrinth 资源时不会失败，会**全部打入包内**（体积可能较大）
- 若未识别到加载器依赖，会提示「导入方需自行选择加载器」——此时导入方仍需手动安装加载器
- 不含存档的导出适合分享；含存档会把你自己的世界一并打包

### 导入本地整合包

入口有两个：

- 「版本」页工具栏「导入整合包」按钮（选择 `.mrpack` 或 `.zip`）
- 直接把 `.mrpack` / `.zip` **拖拽到「版本」页**

1. 启动器先解析包信息，显示包名、MC 版本、加载器与文件数、体积
2. 填写**新版本名称**（默认取包名），并选择是否**版本隔离**：
   - 勾选（默认，推荐）：内容独立存放在 `versions/<新名称>/`，并新建一个版本条目
   - 不勾选：内容直接写入共享的 `.minecraft` 目录，不新建版本条目
3. 点「导入」开始下载与安装；弹窗可「后台导入」，安装完成后提示结果
4. 若包内声明的原版或加载器尚未安装，会**联动自动安装**（原版 → Fabric/Quilt/Forge/NeoForge）
5. 新版本名与已有版本重名时会自动改为「原名 (2)」「原名 (3)」

说明：仅支持 Modrinth 格式（`.mrpack` 或内含 `modrinth.index.json` 的 zip）；
CurseForge 整合包与普通压缩包会给出不支持提示。

## 10. 版本备份与回档

「版本」页选中一个版本 → 行菜单 →「备份与回档」。

### 备份

1. 选择**备份粒度**（三档，可再用下方复选框微调）：
   - **最小**：只备份版本定义（`versions/<版本>/<版本>.json`、同名 `.jar`）与启动器设置
   - **标准**（默认）：该版本的内容——隔离版本备份整个版本目录；共享实例备份
     `mods`、`config`、`resourcepacks`、`shaderpacks`
   - **完整**：标准内容 + 共享 `.minecraft` 目录下的内容目录（用于隔离版本一并留存共享内容）
2. 勾选**附加内容**：世界存档、配置、资源包、光影（随粒度自动预勾选，可手动改）
3. 填写**备份名称**（默认 `<版本名>-<日期>_<时间>`），对话框实时显示预计体积
4. 点「开始备份」，弹窗可「后台备份」；完成后提示备份名称、体积与文件数

### 已有备份 / 回档

对话框下方列出该版本的备份（按时间倒序），每行有：

- **回档**：把该备份的内容覆盖回当前版本；**回档前会自动先备份当前状态**
  （生成名为「回档前自动备份-<时间>」的备份），需二次确认
- **删除**：删除该备份文件与索引记录，需二次确认

底部工具按钮：「打开备份目录」（`<.minecraft>/starcloud/backups`）、「重建索引」
（索引损坏或手工放入 zip 后，按 zip 重建备份列表）。

注意事项：

- **版本正在运行时不可备份或回档**，请先退出游戏
- 备份为 zip 归档；备份与回档均不会删除备份历史（回档只覆盖备份所包含的范围）
- 索引文件为 `<.minecraft>/starcloud/backups/index.json`，可直接复制整个 `backups` 目录迁移

## 11. 账户页

### 离线账户

- 输入玩家名添加；UUID 按 Minecraft 官方离线规则
  （`OfflinePlayer:<name>` 的 MD5 v3）生成，与正版/其他启动器互认
- 同名账户自动去重

### 微软正版账户（设备码登录）

1. 点击「微软登录」→ 显示设备码（如 `ABCD-EFGH`）与验证网址
2. 浏览器打开 `https://www.microsoft.com/link`，输入设备码并登录微软账户
3. 启动器自动完成登录（Xbox → Minecraft 换票）并添加账户、设为默认

登录使用 Minecraft 官方启动器的应用身份；令牌过期后需重新执行设备码登录。

### 默认账户 / 删除

- 每个账户行可「设为默认」；默认账户在首页直接生效
- 删除需二次确认（ContentDialog）

## 12. 设置页

分组卡片布局，修改后点击底部「保存设置」（成功弹出「已保存」提示）：

| 分组 | 项 |
| --- | --- |
| 游戏目录 | `.minecraft` 目录路径（版本/库/资源安装位置） |
| 内存分配 | 单滑块设置最大内存（1 GB ~ 自动上限；自动上限按物理内存的 1/4 计算，最低 2 GB、最高 3/4，如 16 GB 内存约 4 GB）；最小内存固定 512 MB |
| Java | java.exe 路径（留空用系统 java）；「检测系统 Java」；「下载 Java 21 / Java 8（Temurin）」一键托管下载 |
| 下载与外观 | 下载并发数（1-64）；外观（跟随系统 / 浅色 / 深色） |

Java 托管下载位置：`%APPDATA%/starcloud-launcher/java/<主版本>/`。

## 13. 启动器日志页

- 只读显示启动器日志尾部（等宽字体），排查安装/启动问题用
- 日志文件位置：`%APPDATA%/starcloud-launcher/logs/`

## 14. 常见问题

| 现象 | 处理 |
| --- | --- |
| 启动游戏报「找不到 Java」 | 设置页 → 下载 Java 21（Temurin），或手动填入 java.exe 路径 |
| 下载速度慢 | 设置页提高「下载并发数」（默认 16） |
| 下载失败 | 网络问题自动重试；失败后 InfoBar 显示原因，可重试安装（已下载文件自动跳过） |
| 微软登录卡住 | 确认浏览器已完成设备码授权；令牌过期则重新登录 |
| Fabric 安装失败 | 先确认对应原版已安装（下载页） |
| 游戏启动即崩溃 | 查看游戏目录 `logs/latest.log` 与启动器日志页 |
| 界面颜色不对 | 设置页「外观」切回「跟随系统」 |

## 15. 数据位置

```
%APPDATA%/starcloud-launcher/   启动器数据（设置/账户/Java/日志/资源库）
%APPDATA%/.minecraft/           默认游戏目录（可在设置中修改）
```
