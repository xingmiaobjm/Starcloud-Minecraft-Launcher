# Nova 游戏内浮窗（在场阶段）设计

> 日期：2026-09-08
> 状态：已与用户对齐（方向/范围/技术路径/架构/边界均已确认）
> 上游规格：NOVA_DESIGN.md §8（游戏内浮窗）、§3 能力阶段四「在场」；NOVA_INTEGRATION.md §8
> 技术栈：.NET 8 / WinUI 3 / Windows App SDK 1.8（与启动器主体一致）

---

## 1. 目标与范围

为 Nova 补齐第四阶段「在场」能力：游戏运行时以**贴角浮窗**常驻，不切屏就能对话、收提醒、点头确认。

**第一版功能（用户确认"全都要"）：**
1. **对话 + 提案确认**：浮窗内复用 `NovaChatView`，全局会话、时刻候选确认、确认清单零改动直接可用
2. **游戏事件提醒**：订阅 NovaMoments 现有日志事件流（死亡/成就/挑战/战报），主动弹一句话气泡
3. **帧数启发式监测**：纯软件层（进程 CPU/GPU 占用突变 → 疑似卡顿），**明确标注"疑似"**，不使用视觉层 OCR（用户确认）

**明确不做（本轮）：**
- 视觉感知层（DXGI/WGC 采集、OCR 读 F3、VLM 判高光）——真帧数检测后置
- 注入游戏进程的 Present Hook Overlay（方案 B，违背"不碰游戏进程"边界）
- 跨进程 SetParent 子窗口（方案 C，不可行）
- 语音指令

---

## 2. 方案选型（已确认：方案 A）

| 方案 | 形态 | 结论 |
|---|---|---|
| **A. 独立置顶透明窗口** | Nova 自己的 WinUI 3 顶层窗口 | **采用**：同进程复用 NovaChatView/NovaRuntime，零通讯成本，不碰游戏进程 |
| B. 注入 Hook Overlay | Detours 挂游戏 Present | 否决：C++ 注入工程量大、反作弊风险、违背克制边界 |
| C. 跨进程 SetParent | 浮窗设为 MC 子窗口 | 否决：跨进程行为未定义、MC 窗口重建即失效 |

**已知约束**：游戏开**全屏独占**时浮窗被系统盖住 → 检测到独占时自动隐藏，并在主窗口状态栏提示「切无边框窗口模式可显示浮窗」（Minecraft 原生支持无边框）。

## 3. 架构与组件

### 3.1 Core 层：`NovaFpsWatcher.cs`（新增）

启发式卡顿监测服务，`Starcloud.Core/Services/`。

```
输入    GameLauncher 启动游戏时记录的 javaw ProcessId（直接传递，不按进程名猜）
采样    每 3s：
        - CPU%  = Process.TotalProcessorTime 差分 / 间隔 / Environment.ProcessorCount
        - GPU%  = PDH「GPU Engine」计数器按进程实例过滤（可降级）
判定    滑动 60s 窗口：CPU 持续 >85%（≥4 个采样点）且波动剧烈（标准差高）
        → 触发 SuspectedStutter 事件
事件    SuspectedStutter(StutterEvidence { CpuAvg, CpuStdDev, WindowSec, GpuAvailable, GpuAvg })
冷却    同类提醒 10 分钟一次（防提醒风暴）
降级    PDH 不可用 → 仅 CPU，证据注明「数据源：CPU」
        CPU 采样失败 → 帧数提醒整体禁用（静默，不影响其他功能）
诚实性  所有输出标注「启发式推测」，证据只报实测数值，不臆造帧数
```

### 3.2 App 层：`NovaOverlayWindow`（新增）

独立 WinUI 3 Window，随主窗口创建、按需显示。

```
窗口样式   TOPMOST + TOOLWINDOW（不进任务栏、不进 Alt-Tab）
收起态     48×48 圆角 NovaOrb，右下角贴角（距边 16px）
           可拖动，位置记忆到本地设置
展开态     320px 宽毛玻璃面板（max-h 400px）：
           标头（收起按钮）+ NovaChatView（复用组件）+ 输入行
热键       Ctrl+N 全局热键（RegisterHotKey）→ 展开/收起切换
           注册失败 → 提示一次「热键被占用」，点击 Orb 仍可用
气泡提醒   事件提醒以一句话卡片弹出，10s 自动收起
独占检测   每 2s 检查游戏窗口：前台 + rect 覆盖全屏 + 无边框样式
           → 疑似独占 → 浮窗自动隐藏 + 主窗口状态栏提示
崩溃隔离   独立窗口，任何异常不影响游戏与主窗口
```

**复用红利**：浮窗内嵌 `NovaChatView` 后，时刻候选「做成时刻/别管了」、邀请确认清单、LLM 降级链、审计流水——全部零改动直接在浮窗可用（受益于 NovaRuntime 全局状态机）。

### 3.3 改造点（3 处）

| 位置 | 改动 |
|---|---|
| `NovaRuntime` | 订阅 `NovaFpsWatcher.SuspectedStutter` + 转发 NovaMoments 候选/战报事件 → 统一推送浮窗气泡 + 主窗口状态栏联动；持有浮窗引用，游戏启动/退出驱动其显隐 |
| `SettingsPage` | Nova 区新增「游戏内浮窗」开关（**默认关**，开启=显式授权，与许可层同哲学）+ 位置记忆 |
| `MainWindow` | 游戏启动 → 开关开着则唤起浮窗；游戏退出 → 浮窗收本局战报卡后自动隐藏 |

## 4. 交互流（主线）

```
开启「游戏内浮窗」开关 → 启动游戏
  → 贴角 Orb 出现（状态栏同步「Nova: 观察中」）
  → 游戏中死亡/达成挑战
      → Orb 弹一句话气泡（Nova 语气，如"刚才那次凋灵战挺险的"）→ 10s 自动收
  → 疑似卡顿命中
      → 弹证据卡：「CPU 持续 92% 达 90 秒，疑似卡顿（启发式推测）」
      → [看体检方案] [别管了]
  → Ctrl+N 或点 Orb → 320px 面板展开 → 正常对话 / 时刻确认 / 确认清单
  → 退出游戏 → 浮窗收本局战报卡 → 自动隐藏
```

## 5. 错误与降级总表

| 场景 | 处理 |
|---|---|
| PDH GPU 计数器不可用 | 降级仅 CPU，证据卡注明数据源 |
| CPU 采样失败 | 帧数提醒禁用（静默） |
| Ctrl+N 被占用 | 提示一次，点击路径保底 |
| 游戏全屏独占 | 浮窗隐藏 + 主窗口提示切无边框 |
| 浮窗崩溃 | 游戏与主窗口不受影响 |
| 提醒风暴 | 10 分钟冷却 + 气泡 10s 自动收 |

---

## 6. 隐私边界

- 浮窗**零采集**：不读画面、不读剪贴板、不枚举无关窗口——只观测自己启动的 javaw 进程性能计数器
- 开关默认关，开启 = 显式授权；位置记忆仅存本地 settings
- 不注入、不 hook、不改游戏进程

## 8. 交付约定（与 NOVA_DESIGN.md §16 一致）

1. 浮窗是「在场」入口，不是新权限：一切动手动作仍走既有确认清单，不可跳过
2. 提醒文案遵守 Nova 语气：一句话 + 一个按钮，不刷屏；帧数结论必须标注「启发式推测」，只报实测数值
3. 默认关闭，开启 = 显式授权
